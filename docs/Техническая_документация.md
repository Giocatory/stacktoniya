## 1. Обзор и принципы

- **Нет сборки и нет сервера.** Весь проект — статические файлы: HTML, CSS и обычные (не ES-модули) JavaScript-файлы. Достаточно любого статического хостинга или двойного щелчка по `index.html`.
- **Нет внешних зависимостей.** Ни npm-пакетов в рантайме, ни CDN: шрифты лежат локально (`assets/fonts/`).
- **Всё состояние — в браузере.** Схема хранится в `localStorage`; обмен данными — файлами и ссылками.
- **Слоистая разработка.** Функциональность наращивалась последовательными слоями (`v2…v110`): каждый следующий файл дополняет предыдущие, оборачивая функции. Порядок подключения скриптов в `stecktonia/index.html` **важен**.
- **Учебная модель, а не эмулятор.** Консоли Cisco/Huawei/Eltex и Astra Linux — подмножества команд с упрощённой логикой; криптография в VPN — учебная (см. [раздел 16](#16-ограничения-и-принятые-допущения)).

## 3. Симулятор: архитектура

### 3.1. Загрузка

`stecktonia/index.html` подключает файлы по порядку: `core/00-main.js … 12-v13a.js` → `layers/*` → `modules/*`. Все файлы выполняются в **глобальной области** и делят имена верхнего уровня (`const`/`function`/`let`). Отсюда правило: **имена верхнего уровня должны быть уникальны** во всём проекте (были коллизии: `plAdd`, `snap`, `acRules`); для локальных вещей используйте блок `{ … }` или префикс модуля.

### 3.2. Ядро (`scripts/core/`)

| Файл | Содержание |
|---|---|
| `00-main.js` | состояние `S`, типы устройств `T`, утилиты IP (`ip2n`, `n2ip`, `nm`, `same`, `plen`), `save()`, `addDev`, `devClean`, `schemeFix`, `link`/`peer`, `run` (консоль), `draw` (SVG-отрисовка), `side` (боковая панель) |
| `01-v2.js` | L2-обход (`l2all`), `computeRip`, `trip` — пошаговый маршрут пакета (IPv4) |
| `02-v3.js` | история `snap/undo/redo` (до 100 шагов), `peers`, Wi-Fi, имена по умолчанию |
| `06-v7.js` | справка `MAN` (разделы «Инструкции»), `HELP` |
| `09-v10.js` | IPv6 (`trip6`) |
| `11-v12.js` | `CMDS` — справочник команд, `byNm`, `execOn` — выполнение команды на выбранном устройстве |
| `12-v13a.js` | `TPL` — шаблоны схем, `tplLoad` |

### 3.3. Слои (`scripts/layers/`)

Файлы `v14a … v64` добавляют: отчёты, экзамен и ведомость (`v21`), окна «Скрипты и Git» (`v23*`), CI/CD, службы, ufw/iptables, Docker, пользователи и права, значки «?», режимы ГИА и «Профессионалы», консоли Cisco IOS и Huawei VRP, расширенный bash, раскраску вывода (`pAdd` в `v62`) и др. Каждый слой начинается с комментария вида `// ===== vNN: … =====`.

### 3.4. Модули (`scripts/modules/`)

Самостоятельные возможности (префикс `m_`): `m_pcap` (анализатор пакетов), `m_sim` (режим симуляции), `m_rec` (запись сеанса), `m_collab` (совместная работа), `m_ansible`/`m_py`/`m_cyber`/`m_siem`, сетевые темы (`m_routing`, `m_vpn`, `m_ipv6`, `m_ospf3`, `m_bfd`, `m_vrf`, `m_pbr`, `m_redist`, `m_stpx`, `m_vlanx`, `m_vlsm`, `m_ipam`, `m_rchk`, `m_aclaudit`, `m_sla`, `m_span`), российский контекст (`m_eltex`, `m_astra`, `m_gost`), обучение (`m_exnet`, `m_quiz`, `m_assign`, `m_apropos`, `m_matrix`, `m_pages`, `m_cp`, `m_pro`).

### 3.5. Отрисовка

`draw()` строит SVG целиком из состояния `S` (устройства, кабели с изгибами, зоны, заметки), `side()` — боковую панель выбранного устройства. После любого изменения вызывается `ch()` = `save(); draw(); side();`.

### 3.6. Расчёт пути пакета

`trip(d, dst)` (IPv4) и `trip6` (IPv6) вычисляют цепочку шагов `EX[]` с объяснением причины остановки (нет маршрута, ACL, NAT, VLAN, выключен интерфейс, TTL и т. д.). Режим симуляции (`m_sim`) и команды `ping`/`tracert`/`send` пользуются этим результатом. Маршрутизация RIP считается на лету (`computeRip`), OSPF/BGP/VRRP/STP — модулями по текущей конфигурации (без обмена пакетами протоколов: состояние выводится из настроек и состояния интерфейсов).

## 4. Модель данных

Глобальное состояние `S` (сериализуется в JSON):

```js
S = {
  devs:  [ /* устройства */ ],
  links: [ { a, ai, b, bi, id?, ct?, len?, bad?, … } ],  // a/b — id устройств, ai/bi — индекс интерфейса
  c: 0,                                // счётчик id устройств ('d'+n)
  n: { pc: 0, sw: 0, rt: 0 },         // счётчики имён по типам
  flows, notes, zones, …              // потоки, заметки, зоны (создаются по необходимости)
}
```

Устройство:

```js
{ id:'d3', t:'pc'|'sw'|'rt'|…, name:'R1', x, y, mac,
  ifaces:[ {n:'gi0/0', ip:'', mask:'', off?, bfd?, ra?, tun?, …} ],
  gw:'', routes:[ {net, mask, nh, ad?, track?} ],
  // необязательные расширения: acl, acl6, pl (prefix-lists), rmap, pbr, redist, sla, track,
  // span, vm {m} (режим консоли), vend ('cisco'|'huawei'|'eltex'), mand (модель Astra), … }
```

Базовые типы `t`: `pc`, `sw`, `rt`; остальные виды карточек (серверы, Wi‑Fi точки, камеры, ИБП, L3-коммутатор и т. д.) задаются дополнительными полями и расширениями слоёв. Коммутаторы: `k='sw'` — неуправляемый, `'msw'` — управляемый (VLAN), `'l3'` — L3 (тип `'rt'`, порты с `sp`).

Правила: все новые поля устройства — **необязательные** и должны очищаться в `devClean` при импорте.

## 5. Консоль и расширение команд

Консоль — функция `run(c)` из `00-main.js`. Новые команды добавляются **оборачиванием** `run` в модулях:

```js
{ const _r = run;
  run = function (c) {
    const a = String(c || '').trim().split(/\s+/), d = sel && dv(sel);
    if ((a[0] || '').toLowerCase() === 'mycmd') { /* ваша логика, вывод через p('текст') */ return; }
    return _r(c);               // всё остальное — предыдущему слою
  };
}
```

- Вывод — `p(text)` (в обёртке `pAdd` из `v62.js` раскрашивает приглашение, ошибки, предупреждения).
- Выполнить команду на другом устройстве: `execOn(device, 'команда')`.
- Найти устройство по имени: `byNm('R1')`; по id: `dv('d3')`.
- Соседи: `peer(d, i)` (по кабелю), `l2all(d, i)` (через L2-сегмент).
- Изменили состояние — вызовите `ch()`.

## 6. Реестры: CMDS, MAN, TPL, EXNET

| Реестр | Где объявлен | Формат записи |
|---|---|---|
| `CMDS` | `core/11-v12.js` | `[имя, синтаксис, кратко, «зачем это нужно», пример, раздел]` — справочник команд и источник для поиска `apropos` |
| `MAN` | `core/06-v7.js` | `[заголовок, html]` — разделы «Инструкции» (теория + ограничения модели) |
| `TPL` | `core/12-v13a.js` | `{n, d, hint, dev:[[тип, имя, x, y]], link:[[a, ai, b, bi]], cfg:[[устройство, ...команды]]}` — шаблоны; `tplLoad` строит схему и выполняет команды `cfg` |
| `EXNET` | `modules/m_exnet.js` | `{n, min, tag, init: r => ({…}), start: c => …, text: c => '…', …проверки}` — экзаменационные задания (сумма баллов 100, «до настройки 0») |

Добавление записи: `CMDS.push([...])`, `MAN.push([...])`, `TPL.push({...})`. При загрузке шаблона команды `cfg` проверяются: если вывод содержит маркеры ошибок («Использование», «Неверн», «Нет такого»…), ошибка попадает в журнал шаблона — **шаблон с ошибкой в cfg считается дефектом** и ловится тестами.

### 7.1. Ключи `localStorage`

| Ключ | Назначение |

| `netlab` | сериализованное состояние `S` (автосохранение при каждом изменении) |
| `netlab_ui` | настройки интерфейса (`UIS`) |
| `netlab_ct` | собственные задания, созданные пользователем в окне «Задания» (`CT`) |
| `netlab_sxc` | пользовательские задания по скриптам (конструктор) |
| `netlab_sxn` | имя студента для файла результата по скриптам |
| `netlab_sxr`, `netlab_sxt` | прогресс и служебные данные заданий по скриптам |
| `nl_tc` | режим подсветки вывода консоли (`tcMode`) |
| `nl_proj` | режим проектора (`'1'`/`'0'`) |
| `nl_stud` | данные студента для сдачи заданий преподавателя |
| `nl_asg` | задания преподавателя |
| `nl_cm_run`, `nl_cm_<режим>` | текущий запуск режимов ГИА/«Профессионалы» и реестры результатов (до 300 записей) |
| `nl_help` | режим подсказок «?» (`qhMode`) |

Если место закончилось, `save()` один раз выводит предупреждение в консоль и работа продолжается без автосохранения.

### 7.2. Файлы

- **Схема** — JSON состояния `S` (экспорт/импорт); при импорте проходит `schemeFix` и `devClean`.
- **Результат экзамена** — `{app:'netlab-exam', v:1, name, variant, strict, at, sum, max, pc, grade, tasks:[…], sig}`; подпись `sig` — хэш FNV-1a от полей + соль `netlab-exam`. Это защита от случайной правки, а не криптографическая защита.
- **Результат по скриптам** — `{format:'netlab-sx-result', v:1, name, date, total, done:[…]}`.
- **Сдача задания преподавателя** — `*.nlsub.json`, `kind:'nl-sub'`, с печатью `…|NetLab-1`; обрабатывается `pages/journal.html`.
- **Ссылка на копию схемы** — `…/stecktonia/index.html#nl=…` (упакованная схема в адресе, без сервера).
- **Запись сеанса** — `*.nlrec.json`; **захват пакетов** — `stacktoniya.pcap`.

## 8. Безопасность импорта

Любой внешний JSON считается недоверенным:

1. `schemeFix(json)` отвергает всё, что не объект со списком `devs`, и приводит структуру к допустимой.
2. `devClean(d)` проверяет каждое расширяемое поле: адреса и маски (`isIp`/`isMask`), диапазоны чисел, длины строк (<200), ограничивает размеры списков (ACL ≤200, prefix-list ≤50, PBR ≤20…). Некорректное **удаляется**, а не «чинится».
3. Вывод в HTML — через `esc()`.
4. Любое новое поле устройства обязательно добавляйте в `devClean`; иначе испорченный файл может обрушить консоль (так был найден дефект с `acl`/`acl6`).

Подписи файлов (`sig`, печать `|NetLab-1`) — контроль целостности для преподавателя, не защита от подделки злоумышленником.

## 9. Режимы: экзамены, задания, журнал

- **Экзамен** (`layers/v21.js`, `modules/m_exnet.js`): варианты по номеру (детерминированные генераторы `init: r =>`), критерии и баллы, строгий режим, таймер, итог со шкалой оценок, файл результата и ведомость группы.
- **ГИА / «Профессионалы»**: сценарии на 180 минут из нескольких модулей с весами.
- **Задания по скриптам**: банки заданий bash/cmd/ps1, Git, CI/CD, Ansible, Python с автопроверкой и конструктором собственных.
- **Задания преподавателя** (`m_assign`): условие + критерии, выгрузка сдач `*.nlsub.json`.
- **Журнал группы** (`pages/journal.html`): ведомость, поиск подозрительного сходства работ, частые ошибки.
- **Совместная работа** (`m_collab`): ссылка-снимок, комнаты (BroadcastChannel, `netlab-*`), WebRTC-соединение преподаватель ↔ гость через обмен кодами — без сервера.

## 10. Как добавить новую возможность

Образец — модули `m_bfd.js`, `m_ipam.js`, `m_rchk.js`. Типовой набор для одной возможности:

1. **Файл** `scripts/modules/m_<имя>.js` с шапкой `// ===== m_<имя>: что делает =====`.
2. **Команды** — обёртка `run` (раздел 5).
3. **Справка** — `CMDS.push([...])` и раздел `MAN.push([...])` (теория, ограничения модели).
4. **Шаблон** — `TPL.push({...})` с типовой схемой и заготовкой неисправности.
5. **Экзаменационное задание** — запись в `EXNET` (сумма баллов 100, «до настройки 0»).
6. **Очистка при импорте** — новые поля в `devClean`.
7. **Подключение** — тег `<script>` в `stecktonia/index.html` **после** тех файлов, от которых зависит.
8. **Тест** (раздел 11) и запись в пособие (лабораторная работа).

Чек-лист качества: имена верхнего уровня уникальны; ни одной ошибки в консоли браузера; шаблон загружается без ошибок `cfg`; задание в состоянии «до настройки» даёт 0 баллов, после — 100; импорт повреждённых данных не ломает приложение.

## 11. Тестирование

В папке `tests/` лежит набор автотестов, которые запускают настоящий код симулятора в jsdom (браузер не нужен): `cd tests && npm install && npm test`. Подробности — в `tests/README.md`.

- `tests/harness.js` загружает `stecktonia/index.html` со всеми скриптами и стилями и выполняет файл теста в этом окне;
- `tests/cases/tNN.js` — 59 файлов, около 1 000 проверок (команды, шаблоны, экзаменационные критерии, импорт, устойчивость к испорченным данным);
- `tests/run.js` — запускает всё и печатает итог (код выхода 1 при любой ошибке);
- `tests/tfuzz*.js`, `tests/tmut*.js` — фаззинг и мутации.

Схема разработки, которой следовал проект:

- **Регрессионные сценарии** в headless Chromium (Playwright): загрузить `stecktonia/index.html`, выполнить шаги через `tplLoad`, `execOn`, `run`, проверить вывод и состояние `S`. Первое условие каждого теста — **ноль ошибок страницы** (`pageerror`).
- **Фаззинг импорта:** случайные испорченные схемы (удалённые/подменённые поля) не должны вызывать исключений.
- **Мутационные тесты:** ~1000 мутаций состояния и команд над всеми шаблонами — 0 сбоев.
- **Производительность:** загрузка каждого шаблона и серия команд укладываются в бюджет по времени.
- **Скриншотный обход** (`psweep`): открыть все окна и шаблоны, сохранить скриншоты, визуально проверить.

Минимальный пример теста:

```js
const { chromium } = require('playwright');
(async () => {
  const b = await chromium.launch(), p = await b.newPage(), errs = [];
  p.on('pageerror', e => errs.push(e.message));
  await p.goto('file://' + process.cwd() + '/stecktonia/index.html');
  await p.evaluate(() => tplLoad(TPL[0]));
  const out = await p.evaluate(() => { sel = byNm('PC1').id; run('ping 192.168.1.1'); return document.getElementById('out').textContent; });
  console.log(errs.length ? errs : 'ok', out.slice(-120));
  await b.close();
})();
```

Админка и лендинг проверяются так же (см. разделы 12–13): отправка формы с подменой сетевого запроса, импорт CSV/JSON, вход.

## 12. Лендинг

- **Файлы:** `index.html`, `styles/landing.css`, `styles/fonts.css`, `scripts/main.js`, `scripts/config.js`, `assets/*`.
- **Настройка:** только `scripts/config.js` (объект `window.STACK_CONFIG`): `repo`, `github`, `tenchat`, `donate{sbp,card,cardLabel,boosty,yoomoney,crypto}`, `feedback{provider,accessKey,endpoint}`, `publicEmail`. Пустые значения скрывают кнопки; пустой блок донатов показывает заглушку «скоро».
- **Скрипт `main.js`:** ссылки из конфига, донаты (ссылка или «скопировать»), меню, появление блоков (`IntersectionObserver`; без JS всё видно), счётчики, вкладки скриншотов, FAQ, анимированный фон героя (canvas, отключается при `prefers-reduced-motion`), форма.
- **Контакты:** статический блок `#feedback` в `index.html` (Telegram, Max, Email, TenChat, GitHub); формы и сбора данных нет.
- **Дизайн:** тёмная тема (`--bg:#070b14`, `--pr:#4f8cff`, `--ac:#22d3ee`, `--vi:#8b5cf6`), шрифты Manrope и JetBrains Mono (SIL OFL), адаптивная вёрстка (брейкпоинты 980 и 760 px), `img{height:auto}` — иначе атрибуты `width/height` искажают пропорции изображений.
- **Утверждения на странице:** сравнительная таблица и фраза «в России альтернатив нет» сопровождены оговоркой («насколько нам известно», данные могут устареть). Перед публикацией сверьте их с актуальной ситуацией.
- **Скриншоты:** `assets/screens/*.webp` (1920 px). Получены из симулятора Playwright-скриптом: загрузка шаблона → команды в `#in` → `page.screenshot` (`deviceScaleFactor: 2`) → конвертация в WebP.

## 14. Публикация и эксплуатация

1. Выложите **содержимое** `stacktoniya/` в корень статического хостинга (GitHub Pages, Cloudflare Pages, Netlify, обычный хостинг). Все пути относительные — подкаталог тоже допустим.
2. Привяжите домен, включите HTTPS.
3. Заполните `scripts/config.js` и `privacy.html`.
4. Проверьте контакты на странице.
5. Проверьте: главная, `/stecktonia/`, `/privacy.html`, мобильный вид (390 px).
6. Желательно: заголовки безопасности на уровне хостинга (`Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`). Для лендинга достаточно `default-src 'self'; img-src 'self' data:; connect-src 'self' https://api.web3forms.com https://formspree.io; style-src 'self' 'unsafe-inline'`; **для `/stecktonia/` CSP с запретом `eval` и inline-скриптов не подходит** — симулятор использует их.
7. Обновление — повторная загрузка файлов; данные пользователей на сайте не хранятся, миграций нет.

Боевой адрес проекта — `https://stacktoniya.ru/`. Адреса зашиты в `index.html` (canonical, Open Graph, JSON-LD), `privacy.html`, `sitemap.xml`, `robots.txt` и `.htaccess` (редирект на https и без www); при смене домена замените их все.

## 15. Совместимость и историческое наследие

Проект ранее назывался **NetLab** и переименован в «Стектонию» (видимые тексты, имена скачиваемых файлов, SSID Wi‑Fi по умолчанию `Stacktoniya-N`, имя CI-файла `.stacktoniya-ci.yml`). **Внутренние идентификаторы сохранены намеренно**, чтобы не потерять данные пользователей и совместимость с уже выданными файлами:

- ключи `localStorage` (`netlab`, `netlab_*`), канал `BroadcastChannel('netlab-…')`;
- маркеры форматов `netlab-exam`, `netlab-sx-result`, печать `…|NetLab-1`, соль хэша пароля пользователей Linux `$6$netlab$`;
- ссылка копии схемы использует `#nl=`.

Если понадобится полностью убрать старое имя, делайте это единой миграцией с чтением старых ключей и форматов — иначе пользователи потеряют сохранённые схемы, а проверка подписей прежних файлов начнёт отклонять их.

## 16. Ограничения и принятые допущения

- Консоли Cisco/Huawei/Eltex — **подмножества команд** для обучения; не заменяют реальное оборудование и не содержат прошивок. Названия вендоров принадлежат их владельцам, проект с ними не связан.
- **Astra Linux** — учебная модель мандатного доступа (учётная запись root не ограничивается); не заменяет сертифицированные средства защиты.
- **Криптография** (IPsec, WireGuard, ГОСТ-профиль) — учебная имитация без реальных шифров; ключи и сертификаты — условные значения.
- **VRF-lite** (`m_vrf.js`) реализован без изменения ядра: перед обработкой пакета маршрутизатор «видит» только интерфейсы и маршруты таблицы входного интерфейса (`vfShadow`). Динамические протоколы работают только в глобальной таблице; RD/RT, утечка маршрутов и MPLS не моделируются; команд VRF в консолях Cisco/Huawei/Eltex нет.
- **Протоколы** (OSPF, BGP, VRRP, BFD, STP…) не обмениваются настоящими пакетами: итоговое состояние вычисляется из конфигурации.
- **Режимы ГИА, ДЭ, «Профессионалы»** — учебные модели формата, а не официальные материалы.
- **Подписи файлов** защищают от случайных искажений, а не от намеренной подделки.
- **Производительность:** схемы до нескольких десятков устройств работают плавно; отрисовка — SVG целиком.
- **Браузеры:** современные Chrome, Edge, Firefox, Яндекс Браузер на компьютере с мышью и клавиатурой; сенсорные устройства поддерживаются ограниченно.
