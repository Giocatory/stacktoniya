# Автотесты симулятора

Тесты запускают настоящий код `stecktonia/` в jsdom (браузер не нужен) и проверяют команды консоли, шаблоны схем, экзаменационные задания, импорт и устойчивость к испорченным данным.

```bash
cd tests
npm install        # один раз: ставит jsdom
npm test           # все тесты из cases/
node run.js t11    # только файлы, в имени которых есть «t11»
```

- `harness.js` — загружает `stecktonia/index.html` (все скрипты и стили) в jsdom и выполняет в нём файл теста; по умолчанию берёт симулятор из `../stecktonia/`, другой путь задаётся переменной `F`.
- `cases/tNN.js` — тесты по версиям функций (строки `PASS …` / `FAIL …`).
- `tfuzz*.js`, `tmut*.js` — фаззинг и мутации: портят импортируемую схему и проверяют, что программа не падает (запуск: `NODE_OPTIONS=--max-old-space-size=6000 node harness.js tmut2.js` — тесту нужно много памяти).

Новый тест: создайте `cases/tNNN.js`, в начале файла определите `const ok=(c,m)=>console.log((c?'PASS ':'FAIL ')+m)`, дальше используйте `run('команда')` (после `sel=id устройства`), `byNm('R1')`, `tplLoad(шаблон)`, `trip(устройство,'ip')` — образец: `cases/t116.js` (VRF-lite).
